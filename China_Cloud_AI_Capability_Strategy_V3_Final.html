01

Roadmap

Both workstreams use the same read-only AWS tool layer. The Q4 target is a working query agent and a small alert-analysis pilot. A new deployment platform is outside this scope.

01 / Ask CloudOps

Knowledge and Resource Queries

Build the ECS-hosted MCP services, connect them to Copilot Studio, and share the agent with a small engineering group. Answers should include sources, account scope and query time.

02 / Review alerts

Scheduled Email Analysis

Use Power Automate to scan an approved alert mailbox. An agent checks AWS evidence and runbooks; the workflow saves the result in SharePoint and posts a summary to Teams.

STEP 01

Connect One Account

Choose an AWS China account, region and resource type. Test HTTPS, MCP authentication and the target read-only role.

Pass: a real query works; an unauthorized account and a write request are denied.

STEP 02

Share the Query Agent

Add approved knowledge sources and a small set of resource tools. Test with someone other than the agent maker.

Pass: users can trace answers and cannot exceed the agreed scope.

STEP 03

Pilot One Alert Type

Connect a dedicated mailbox, persist pending events, call the analysis agent, and publish results to SharePoint and Teams.

Pass: background authentication works; repeated scans do not duplicate results.

STEP 04

Expand After the Pilot

Add accounts and alert types only after reviewing failure rates, query load and support needs. Decide separately on CMDB or AliCloud integrations.

Pass: each extension has a defined owner, data scope and test set.

Confirmed Placement. Microsoft global commercial cloud connects to MCP services hosted on ECS in AWS China. Connectivity, authentication and unattended execution still need testing.

Outside This Phase: No resource changes, automatic remediation or deployment tools in this phase. B4 belongs to the later Agentic Workforce project. TechPages remains an HTML-sharing service, not the agent portal.

Architecture and User Scenarios

Engineers ask questions in Copilot or Teams. A scheduled workflow sends alerts to an analysis agent. Both use the same approved AWS queries.

What People Would Use It For

Cloud engineer

Check a Resource

“Which approved resources match this tag, and what is their current configuration?”

A scoped resource list with configuration, account, region and query time. No changes are made.

Copilot / Teams

Cloud engineer

Find the Right Guidance

“What does our runbook say about this service, and which AWS documentation applies?”

Relevant internal guidance and public documentation, with the sources kept distinct.

Copilot / SharePoint

On-call engineer

Review an Email Alert

“What happened, what evidence supports it, and what should I check next?”

Facts, possible causes and next checks. Missing evidence stays visible; a person decides the response.

Teams summary / SharePoint detail

Workflow owner

Recover a Failed Run

“Did analysis fail, or did the Teams notification fail?”

Separate processing and delivery states, so a notification retry does not rerun completed analysis.

SharePoint task record

  • Keep public AWS documentation separate from internal SharePoint knowledge. Public documentation does not need a target-account role.
  • Use separate Query and Alert Analysis agent configurations if their knowledge, access or output needs differ. They share MCP services, not conversation history.
  • Use native Microsoft channels first. A web-chat snippet embeds an interface; it does not move the agent or its permissions into the web page.
03

Technical Plan

Copilot Studio handles reasoning. MCP exposes narrow queries. IAM and server-side authorization decide what those queries may read.

Query path

Connect Copilot Studio to MCP

  1. Publish approved MCP endpoints over HTTPS using Streamable HTTP. Test the connection from Copilot Studio, not just a laptop.
  2. Validate interface credentials at the backend. Entra OAuth is a proposed enterprise addition; the reference repository does not establish it as implemented.
  3. Map an approved account alias to a target role on the server. Do not accept an arbitrary role_arn selected by the model.
  4. Return structured evidence with source, account, region, query time and any limits or failures.
Scheduled path

Keep Processing State in the Workflow

  1. Scan the approved mailbox with pagination, an overlap window and a stable event key.
  2. Save a pending task before advancing the scan watermark.
  3. Call Execute Agent and wait with a fixed instruction and separate alert payload. Start a fresh conversation for each independent event.
  4. Validate the response, save the analysis, then post the Teams summary. Track notification retries separately.

IAM Role Responsibilities

ECS Execution Role

Container operations such as pulling images and sending runtime logs.

ECS Task Role

Runtime access for the MCP service; limit AssumeRole to approved target roles.

Target Read-Only Role

IAM allows the selected resource APIs and log groups. The MCP service bounds time windows, result size and returned fields. Exclude secrets and unnecessary object content.

Proposed Tool Set

These names are interface examples, not a claim that the repository already provides them.

search_public_aws_docs

Public documentation and citations.

list_resources

Approved account, region and resource-type filters.

get_resource_configuration

Configuration, tags and current state.

query_alert_evidence

Bounded event and log evidence for an alert.

Background Identity. Background runs must work without interactive sign-in. Test token refresh, conditional access and connection recovery. Do not assume the native MCP connection supports the required client_credentials mode.

Analysis Record: Keep the event key, analysis status, facts, possible causes, evidence references, missing data, next checks and analysis time. Store delivery status separately.

Reference, Not a Production Deployment: mcp-hub-on-ecs provides a hosting starting point. Narrow tools, enterprise authentication and least-privilege policies still need implementation and testing. Provision infrastructure through the approved company process.

04

Risks and Challenges

The cloud placement is confirmed. Integration and operational readiness still need testing before a wider release.

01

Cross-Cloud Access

A local client test does not prove that Copilot Studio can reach the AWS China endpoint reliably.

Test discovery, queries, timeouts and concurrent sessions from the actual Microsoft environment.

Release Check: Repeatable cloud-to-cloud calls with recorded failures and recovery.

02

Identity and Authorization

Agent sharing, MCP credentials and AWS access are separate controls. A shared connection may not identify each user.

Verify identity propagation and enforce account mappings on the server. Until then, keep users within one agreed access scope.

Release Check: Unauthorized accounts and roles are denied; the audit trail identifies the calling connection or user accurately.

03

Unattended Authentication

A chat session can succeed while a scheduled run later stops for sign-in or consent.

Test the background connection, token lifecycle and recovery path. Choose an approved adapter only if the native connection is insufficient.

Release Check: Scheduled analysis completes without an online user, including after credential refresh.

04

Analysis Quality

Partial logs or a wrong runbook can produce a convincing but unsupported explanation.

Require citations, distinguish facts from hypotheses, and test missing-data cases. Treat email and log instructions as untrusted content.

Release Check: A reviewer can trace every material claim or see why it could not be confirmed.

05

Duplicates and Failures

Repeated scans, empty responses and failed notifications can lose or duplicate work.

Persist task state, enforce a unique event key, and separate analysis retries from delivery retries.

Release Check: Replay, timeout and notification-failure tests produce no silent loss or duplicate publication.

06

Tenant Policy and Operating Load

DLP, capacity, mailbox access and query volume can limit a pilot even in the global commercial cloud.

Check policy and licensing, cap query scope and concurrency, and assign support responsibility.

Release Check: The pilot has permission, capacity and an agreed support plan.

The 21Vianet connector limitation is not applicable to this confirmed global-cloud architecture. It is not a reason to move the AWS China MCP services.
